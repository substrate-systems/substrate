Fields and focus
Focus is “current”, so it may be amber. Proposed: a field takes an amber border, a soft amber ring and an amber caret; buttons and links get a ring with a small gap, so it reads on any fill. Paddle’s inline checkout has its own styling options in Paddle’s dashboard (focus border and shadow, borders, roundness, system fonts, text, buttons, links), so the fields inside Paddle’s frame can match ours. Errors stop using amber: amber now means focus. One new value: the light placeholder #757068 (today’s faint #8A857B is 3.46:1 on the field, below 4.5).

Mouse clicks don’t show the ring (focus-visible); the keyboard does. The gap keeps the ring readable on the ink button and on the paper.
Validation: ours, never the browser’s
No browser bubblesForms use novalidate. We check, we word the message, we place it.
Not while typing the first timeA field is judged when the person leaves it or presses the button.
Then liveOnce a field has shown an error, it is checked on every keystroke, so the error goes the moment it is fixed.
On the buttonEvery field is checked; focus moves to the first one with an error. Nothing typed is cleared.
Server answersA wrong password lands on the password field, worded the same way. Never say whether an account exists.
One line, heldHint and error share one line under the field, held at 18 px, so nothing jumps. Errors stay under about 45 characters.
How an error looksThe border turns full ink and a little heavier, the line under it turns full ink. No icon, no red, no amber: amber is focus.
Optional, not requiredMark the rare optional field “(optional)”. No asterisks.
For screen readersaria-invalid on the field, aria-describedby to its line, and the line is a polite live region.
